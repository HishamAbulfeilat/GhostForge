# /a11y Command

## Purpose
Run a WCAG 2.1 AA accessibility audit, explain issues, and optionally auto-fix common problems.

## Usage
| Command | Description |
|---|---|
| `/a11y` | Run a full accessibility audit |
| `/a11y --component [name]` | Audit a specific component |
| `/a11y --fix` | Auto-fix common issues where safe |
| `/a11y --report` | Generate an HTML accessibility report |

## Examples
```bash
/a11y
/a11y --component LoginForm
/a11y --fix
/a11y --report
```

## Audit checklist
- Color contrast (4.5:1 minimum)
- Alt text for images
- ARIA labels on interactive elements
- Keyboard navigation (tab order, focus visible)
- Screen reader compatibility
- Form labels and error messages
- RTL support (Arabic)
- Touch target size (min 44x44px mobile)
- Semantic HTML (headings hierarchy, landmarks)
- Animation (`prefers-reduced-motion`)

## Output format
```text
♿ Accessibility Audit — WCAG 2.1 AA

🔴 Critical (must fix):     2 issues
🟡 Serious (should fix):    5 issues
🟢 Minor (nice to fix):     8 issues

Score: 71/100 — Partial compliance
```

## What AI does
1. Scans components, routes, forms, and interaction patterns for WCAG 2.1 AA issues.
2. Prioritizes findings by severity and user impact.
3. Explains fixes in practical UI terms for web or mobile contexts.
4. When `--fix` is used, applies safe accessibility improvements first and re-checks the result.
5. When `--report` is used, organizes findings into a shareable report for QA or stakeholders.
